# 🃏 CARD-003 — ***검사기가 값의 「길이」를 증거로 읽는다***

> 함정 카드 · 재료 · 2026-09-15
> 🔒 이런 함정은 교재로는 못 만듭니다 — **밟아야 생깁니다.** 그래서 ⑤에 붙여넣어 돌릴 것을 답니다.

## ① 제목 (기전으로)
**필수 칸이 「비어 있지 않다」는 이유로 통과 표시가 된다** — 검사기가 값의 *형태*가 아니라 *길이*를 본다.
⇒ 가장 크게 다치는 사람은 **「없습니다」라고 정직하게 적어 넣은 사람**이다.

## ② 겉보기
```
· 표에 초록이 찍힌다. 칸이 채워져 있으니 「제출됨」으로 보인다.
· 제출자는 «백업이 없습니다»라고 ★사실대로 적었는데 · 화면에는 ⭕ 로 나온다.
· 아무도 그 줄을 다시 안 본다 — ★초록은 「앎」이라 ***사람을 안 부른다***.
```

## ③ 기계가 낸 수 (⛔형용사 없음)
```
· 서로 다른 저자 · 서로 다른 도구 ★둘 · 발견 간격 ★90분 · ★같은 기전
· 도구 A : 승인 해시 칸에 ★「0」 64자 ⇒ 통과 · ★자체 통제 45칸이 ★전부 초록
           ⇒ 그 통제는 ***제작자가 의도한 동작의 재현***이었고 · 적대적 입력 칸 ★0
· 도구 B : 「백업 없음」이라 적은 ★산문 문자열 ⇒ ⭕ 렌더 (근거 ＝ ★문자열 길이)
· 아래 ⑤ 재현 : rc ★1 · 순진한 검사가 초록을 준 ★검증 불가 건 ★1 / 3
```

## ④ 기전
필수 필드를 `if value:` 로 검사하면, 파이썬·셸·JS 어디서나 **비어 있지 않은 모든 문자열이 참**이 된다.
그런데 사람이 그 칸에 넣는 값은 세 종류다 — **① 진짜 값 · ② 「없다」는 정직한 서술 · ③ 빈 칸**.
길이만 보는 검사기는 ①과 ②를 **구별하지 못하고**, ③만 잡는다.
⇒ 결과가 뒤집힌다: **아무것도 안 쓴 사람은 걸리고 · 「없다」를 써 넣은 사람은 통과한다.**
⇒ 🔒 ***빈 칸을 요구하는 검사는, 「없다」라고 적는 사람을 벌한다.***

## ⑤ 재현 (붙여넣어 돌리면 ★빨강)
```python
import re, sys
RECEIPTS = [
    {"id":"r1","digest":"e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
     "backup":"/var/backups/r1.bak"},                                  # 정상
    {"id":"r2","digest":"UNAVAILABLE_SEE_NOTE",
     "backup":"No prewrite backup exists; the change is a two-line reversal."},  # 정직한 「없음」
    {"id":"r3","digest":"","backup":""},                               # 그냥 빈 칸
]
SHA256 = re.compile(r"^[0-9a-f]{64}$")
def check_naive(r):   return bool(r["digest"]) and bool(r["backup"])
def check_strict(r):
    if not r["digest"] and not r["backup"]:      return "NOT_MEASURABLE"
    if not SHA256.match(r["digest"]):            return "NOT_MEASURABLE"
    if not r["backup"].startswith("/"):          return "NOT_MEASURABLE"
    return "VERIFIABLE"
naive  = [r["id"] for r in RECEIPTS if check_naive(r)]
strict = {r["id"]: check_strict(r) for r in RECEIPTS}
bad = [i for i in naive if strict[i] != "VERIFIABLE"]
print("순진한 검사 ⇒ 통과:", naive); print("형태 검사 ⇒", strict)
print("🔴 초록을 준 검증 불가 건:", bad, f"({len(bad)}건)")
sys.exit(1 if bad else 0)
```
```
[측] 출력 : 순진한 검사 ⇒ ['r1', 'r2']  ·  형태 검사 ⇒ r2 = NOT_MEASURABLE  ·  rc ★1
```

## ⑥ 처방
```
① 필수 필드는 ★형태로 검사한다 —  해시는 `^[0-9a-f]{64}$` · 경로는 절대경로 · 시각은 파싱되는가
② 판정을 ★세 갈래로 벌린다 : 참 ⊥ 거짓 ⊥ ***못 쟀음***  ⇒ ⛔「못 쟀음」을 초록으로 접지 않는다
③ 행이 여럿이면 ***집계는 ★가장 약한 행을 따른다*** — 합을 내면 약한 행이 묻힌다
④ 「없다」를 적을 ★전용 칸을 준다 — 그래야 정직이 ★벌받지 않는다
```
> ⚠️ **이 처방이 쓰는 재료를 다른 검사도 쓰고 있지 않은가**
> ```
> 형태 검사는 ★같은 필드를 ★다른 검사도 「채워져 있으니 있다」로 쓰고 있을 수 있다.
> ⇒ 형식을 조이기 前에 ★그 필드를 읽는 자리를 ★전부 세어라 — 한 곳만 조이면 ★나머지가 옛 뜻으로 읽는다.
> ⇒ 그리고 형태 검사를 ★통과한 값은 ***여전히 대조가 필요하다*** — ⑦ 참조.
> ```

## ⑦ 이 카드가 주장하지 않는 것
```
⛔ 「형태 검사를 붙이면 안전하다」 — 아니다. 형태는 ***★형태까지***다.
   위 r1 의 해시는 ★형태가 맞지만 ★그 파일의 해시인지는 ★아무도 안 쟀다
   ⇒ ***★재는 손과 ★대조하는 손은 갈라져 있어야 한다***
⛔ 「제출자가 잘못했다」 — ⛔반대다. ★정직하게 적은 쪽이 ★벌을 받았다
⛔ 「이건 흔한 초보 실수」 — [측] ★두 저자 · ★90분 · ★같은 병 ⇒ ★렌더러가 흔히 빠지는 모양
⛔ 「자체 통제 n/n 통과가 이걸 잡는다」 — ★그 통제를 ★같은 손이 썼다면 ★안 잡는다
```
