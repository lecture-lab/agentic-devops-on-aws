# 🃏 CARD-001 — ***가드가 한 번도 막지 않았다*** (등록 시점 문자열 전개)

분류 `쉘/스케줄러` · 난이도 ★★★ · 실측 회차 있음 · 카드 형식 v0.1

## ② 겉보기
```
스케줄 작업에 「사람이 쓰는 중이면 실행하지 말라」는 ★가드를 앞에 달았습니다.
작업은 ★정상 종료(0). 가드도 있습니다.
⇒ ⚠️ ***★화면에 보이는 것만으로는 ★이상한 데가 없습니다*** — [측] 저는 ★이 상태를 ★이틀 지나쳤습니다.
   (⛔「아무도 모른다」고 쓰지 않습니다 — ★남의 머릿속은 ★제가 안 쟀습니다.)
```
## ③ 기계가 낸 수 [측]
```
가드 스크립트 단독 실행        : rc 12  (= 「사람이 쓰고 있다」)
같은 순간 스케줄 작업의 결과   : rc 0   ⊥ ★대상 프로그램이 ★실행됨
⇒ ⇒ ★A/B 로 세 보니 ***가드가 12를 내는 동안에도 대상이 매번 돌았습니다.***
```
## ④ 기전 — ★세 겹이 겹쳐야 이 버그가 납니다
```
1) 작업 등록 명령줄을 ★큰따옴표 문자열로 만들었습니다
   ⇒ 그 안의 「직전 종료코드」 변수가 ***★등록하는 순간*** 전개됩니다(그때는 ★빈 값)
   ⇒ 등록된 명령줄은 :  if ( -ne 0 ) { exit }      ← ★왼쪽이 사라졌습니다
2) 그 쉘은 ` -ne ` 를 ***★명령 이름***으로 읽습니다 ⇒ 「명령을 찾을 수 없음」
3) 그 예외는 ***★중단성이 아닙니다***(non-terminating) ⇒ 스크립트는 ★다음 줄로 갑니다
⇒ ⇒ 🔒 ***세 겹 중 ★하나라도 없으면 이 버그는 안 납니다.*** 그래서 눈으로는 안 보입니다.
```
## ⑤ 재현 — ★붙여넣어 돌리면 빨강이 납니다
```
ⓐ 가드가 「막는다」를 내는 상태를 만든다        ⇒ 가드 단독 rc = 12 확인
ⓑ 같은 순간 ★작업을 돌린다                     ⇒ 대상이 돌았는지 ★대상의 산출물로 확인
ⓒ ★등록된 명령줄을 ★그대로 읽어낸다            ⇒ 변수 이름이 ★남아 있는지 ★문자열로 확인
⇒ 🔒 ***★가드의 rc 를 믿지 말고 ★등록된 명령줄을 읽으십시오.*** 거기 답이 글자로 있습니다.
```
## ⑥ 처방 — ★세 겹을 ★세 곳에서 끊습니다 (한 곳만 고치면 ★남습니다)
```
1) 변수를 ★등록 시점에 전개되지 않게 ★이스케이프한다
2) 작업 안에서 ★예외를 중단성으로 올린다 (오류 발생 시 ★멈추게)
3) 🔒 ***★검증자를 하나 더 둔다*** : 등록된 명령줄에 ★그 변수 이름이 ★문자로 있는지 확인하고
   ⛔없으면 ★등록 자체를 거부한다(rc 13)
⚠️ ⑥의 점검문장 : ***이 처방이 쓰는 재료를 ★다른 검사도 쓰고 있지 않은가?***
   (여기선 「등록된 명령줄 문자열」을 ★검증자만 씁니다 ⇒ ⭕독립)
```
## ⑦ 이 카드가 주장하지 않는 것
```
⛔ 「그 쉘이 나쁘다」 — ★문자열 조립으로 명령을 만드는 ★모든 곳의 함정입니다
⛔ 「가드를 쓰지 말라」 — ★반대입니다. ***가드는 ★자기가 막았다는 것을 ★증명해야 합니다.***
🔒 한 줄 : ***★빨강을 못 내는 가드는 가드가 아니라 ★장식입니다.***
```
