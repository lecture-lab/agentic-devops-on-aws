# 🃏 CARD-002 — ***ssh 로 들어간 방과 사람이 보는 방은 다른 방이다***

분류 `데스크톱 자동화` · 난이도 ★★★★ · 실측 회차 있음 · 카드 형식 v0.1

## ② 겉보기
```
GUI 프로그램을 원격으로 띄우고 ★창을 셌더니 ***0개***. 그래서 「실행이 실패했다」고 결론.
그 순간 ★사람의 화면에는 ***그 프로그램이 문서를 열고 서 있었습니다.***
```
## ③ 기계가 낸 수 [측]
```
원격(비대화형)에서 센 창 수        : ★0        ⇒ 「무한 대기」로 판독함
같은 순간 대화형 세션에서 센 창 수 : ★30       ⇒ 클래스·제목·가시성 ★전부 정상
⇒ ⇒ 🔴 ***문서 생성 호출은 ★성공했습니다.*** 틀린 것은 ★계측기의 위치였습니다.
```
## ④ 기전 — ★층이 넷이고 서로 직교합니다
```
세션 ID ⊥ 윈도스테이션 ⊥ 데스크톱 ⊥ 가상 데스크톱   ← ★넷이 ★따로 놉니다
원격 로그인은 ★사람이 보는 세션이 ★아닌 곳에 들어갑니다.
그리고 ★창 열거 함수는 ***호출한 스레드가 붙어 있는 데스크톱만*** 봅니다.
⇒ ⇒ 🔒 ***0 은 「없다」가 아니라 「★여기서는 안 보인다」였습니다.***
```
## ⑤ 재현
```
ⓐ 원격 비대화형으로 GUI 앱을 띄운다 → 창 열거 ⇒ ★0
ⓑ 같은 순간 ★대화형 세션에서 같은 열거를 한다 ⇒ ★0 이 아님
ⓒ 두 곳에서 ★세션 식별자와 ★윈도스테이션 이름을 같이 찍는다 ⇒ ★다릅니다
```
## ⑥ 처방
```
1) 대화형 세션 안에서 돌 ★다리를 하나 두고 · ★조작과 계측을 ★둘 다 그 위로 옮긴다
2) 🔴 ***★다리를 놓을 때 ★일꾼만 옮기고 ★계측기를 안 옮기는 실수가 납니다***
   ⇒ ⭕ 점검 : ***★조작과 판정이 ★같은 방에 있는가?*** (★다른 방이면 판정은 ★0 이 됩니다 — [측] 제 실측 1회 ＋ ★열거 함수가 ★호출 스레드의 데스크톱만 본다는 기전)
3) 판정면은 ★가능하면 화면이 아니라 ★파일/DB 로 — ***★환경을 덜 요구하는 검사가 ★더 자주 잽니다***
```
## ⑦ 이 카드가 주장하지 않는 것
```
⛔ 「원격으로는 GUI 자동화를 못 한다」 — ★다리를 놓으면 됩니다
⛔ 「0 을 보면 무조건 의심하라」 — ★0 을 ★어디서 셌는지를 같이 적으라는 것입니다
🔒 한 줄 : ***★계측기의 위치를 적지 않은 수는 ★수가 아닙니다.***
```
